# Урок 1: Знаёмства з AI-інструментамі распрацоўкі

Мэта гэтага ўрока — пазнаёміцца з сучаснымі AI-інструментамі для распрацоўкі і пачаць праз іх працаваць з рэальным праектам. Мы разгледзім **Cursor**, **VS Code + GitHub Copilot** і **Claude Code**, выканаем першыя заданні, запусцім TypeScript-код і навучымся даваць ШІ дастаткова кантэксту, каб ён дапамагаў, а не ствараў хаос.

Гэты ўрок не пра глыбокую архітэктуру агентаў. Ён пра практычны старт: адкрыць праект, задаць пытанне па кодзе, папрасіць змяніць файл, запусціць вынік і праверыць diff.

---

## Што павінна атрымацца пасля ўрока

Пасля ўрока вы зможаце:

- адкрыць гэты рэпазіторый у Cursor або VS Code;
- карыстацца AI-чатам для пытанняў па праекце;
- дадаваць файлы ў кантэкст праз `@file`, `#file`, адкрытыя файлы або вылучаны код;
- запускаць Claude Code з кораня праекта і даваць яму абмежаваныя задачы;
- ствараць і змяняць TypeScript-файлы з дапамогай AI;
- запускаць прыклады праз Bun;
- правяраць вынік праз diff і каманды;
- разумець, навошта патрэбныя інструкцыі, `AGENTS.md`, скілы і MCP, нават калі ў гэтым уроку мы толькі знаёмімся з імі.

## 2. Якія інструменты разглядаем

### Cursor

Cursor — рэдактар на базе VS Code, у якім AI-функцыі ўбудаваныя ў асноўны workflow. Ён зручны для пачатку, бо ў ім лёгка дадаваць файлы ў кантэкст, рабіць inline-праўкі і запускаць агентурныя змены.

Што паспрабаваць:

- Chat для пытанняў па праекце;
- Inline Edit для праўкі вылучанага кода;
- Agent / Composer для стварэння або змены некалькіх файлаў;
- `@file`, `@folder`, `@codebase` для кантэксту.

### VS Code + GitHub Copilot

VS Code з GitHub Copilot — добры выбар, калі вы хочаце застацца ў звычайным VS Code. Тут важна яўна паказваць кантэкст: адкрываць патрэбныя файлы, выкарыстоўваць `#file`, `#selection`, `#codebase`, калі яны даступныя.

Што паспрабаваць:

- autocomplete праз `Tab`;
- Copilot Chat;
- Inline Chat;
- Copilot Edits або Agent Mode, калі даступна ў вашай версіі.

### Claude Code

Claude Code — агент у тэрмінале. Ён зручны, калі трэба працаваць з усім рэпазіторыем: прачытаць файлы, змяніць код, запусціць каманды і даць summary.

Што паспрабаваць:

- задаць пытанне па структуры праекта;
- папрасіць змяніць толькі адзін файл;
- запусціць Bun-скрыпт;
- паглядзець, якія файлы змяніліся.

## 3. Першае заданне: спытаць AI пра праект

Адкрыйце корань рэпазіторыя `RAG` у выбраным інструменце.

### У Cursor

Адкрыйце Chat і спытайце:

```text

Адкажы па-беларуску і спасылайся толькі на гэтыя файлы.
```

### У VS Code + Copilot

Адкрыйце `README.md` і `lesson1_ai_ide/README.md`, потым у Copilot Chat:

```text
#file:README.md #file:lesson1_ai_ide/README.md
Растлумач, якая мэта Урока 1 у гэтым курсе.
Адкажы па-беларуску і спасылайся толькі на гэтыя файлы.
```

### У Claude Code

З кораня праекта дайце задачу:

```text
Прачытай README.md і lesson1_ai_ide/README.md.
Растлумач, якая мэта Урока 1.
Нічога не змяняй у файлах.
```

Чаканы вынік: AI павінен адказаць па файлах праекта, а не агульнымі словамі пра AI-рэдактары.

## 4. Другое заданне: запусціць TypeScript-прыклад

У гэтым уроку ёсць некалькі маленькіх TypeScript-файлаў. Яны не выклікаюць LLM і не патрабуюць API-ключоў. Гэта матэрыял для жывой працы на занятку: іх можна запускаць, тлумачыць праз AI, выпраўляць і пашыраць.

Запусціце ўсе прыклады:

```bash
bun run lesson1_ai_ide/index.ts
```

Або асобна:

```bash
bun run lesson1_ai_ide/01_calculator.ts
bun run lesson1_ai_ide/02_text_stats.ts
bun run lesson1_ai_ide/03_task_list.ts
bun run lesson1_ai_ide/04_command_helper.ts
```

Што паглядзець:

- `01_calculator.ts` — просты калькулятар, у якім ёсць што палепшыць: апрацоўка дзялення на нуль і паўторная логіка;
- `02_text_stats.ts` — аналіз тэксту, дзе можна папрасіць AI знайсці недакладнасць у падліку сказаў і слоў;
- `03_task_list.ts` — спіс задач урока, які можна фарматаваць, фільтраваць і пашыраць;
- `04_command_helper.ts` — падказкі па камандах, у якія можна дадаваць новыя каманды для курса.

Пасля запуску папрасіце AI растлумачыць адзін з файлаў.

Прыклад для Cursor:

```text
@file lesson1_ai_ide/01_calculator.ts
Растлумач гэты файл пачаткоўцу. Што ён паказвае пра працу з AI-інструментамі?
```

Прыклад для VS Code:

```text
#file:lesson1_ai_ide/01_calculator.ts
Растлумач гэты файл пачаткоўцу. Што ён паказвае пра працу з AI-інструментамі?
```

Прыклад для Claude Code:

```text
Прачытай lesson1_ai_ide/01_calculator.ts.
Растлумач, што робіць гэты файл.
Нічога не змяняй.
```

## 5. Трэцяе заданне: змяніць код праз AI

Цяпер зробім першую маленькую змену ў TypeScript-файле.

Адкрыйце `lesson1_ai_ide/01_calculator.ts` і папрасіце AI выправіць праблему з дзяленнем на нуль.

Промпт:

```text
У lesson1_ai_ide/01_calculator.ts выправі divide так, каб дзяленне на нуль не вяртала Infinity.
Няхай функцыя кідае памылку з зразумелым паведамленнем.
Дадай try/catch у прыклад запуску, каб праграма не падала.
Не мяняй назвы функцый.
Пасля змены падкажы, якой камандай запусціць файл.
```

Запусціце:

```bash
bun run lesson1_ai_ide/01_calculator.ts
```

Чаканы вынік: прыклады складання, аднімання, множання і звычайнага дзялення працуюць, а дзяленне на нуль выводзіць зразумелую памылку.

Пасля гэтага паглядзіце diff у вашым рэдактары або праз git:

```bash
git diff -- lesson1_ai_ide/01_calculator.ts
```

## 6. Чацвёртае заданне: стварыць новы файл праз AI

Папрасіце AI стварыць файл `lesson1_ai_ide/05_first_agent_task.ts`.

Промпт:

```text
Ствары lesson1_ai_ide/05_first_agent_task.ts.
У файле зрабі масіў задач для AI-агента: title, allowedFiles, forbiddenFiles, checkCommand.
Дадай функцыю, якая выводзіць задачы ў кансоль у зручным выглядзе.
Не выкарыстоўвай знешнія бібліятэкі.
Файл павінен запускацца праз Bun.
```

Пасля стварэння запусціце:

```bash
bun run lesson1_ai_ide/05_first_agent_task.ts
```

Калі файл працуе, папрасіце AI палепшыць фармат вываду, але абмяжуйце задачу:

```text
Палепшы толькі фармат console.log у lesson1_ai_ide/05_first_agent_task.ts.
Не змяняй структуру дадзеных і не дадавай бібліятэкі.
```

Гэта практыка паказвае галоўнае правіла AI-распрацоўкі: чым дакладней межы, тым менш нечаканых змен.

## 7. Як даваць кантэкст

Кантэкст — гэта ўсё, што AI бачыць перад адказам: prompt, файлы, вылучаны код, памылкі, diff, вынікі каманд і правілы праекта.

Для пачатку запомніце простую схему:

```text
Мэта:
<што трэба зрабіць>

Кантэкст:
<якія файлы або памылкі ўлічыць>

Межы:
<што можна змяняць і што нельга>

Праверка:
<якую каманду запусціць>
```

Прыклад:

```text
Мэта:
Выправіць дзяленне на нуль у lesson1_ai_ide/01_calculator.ts.

Кантэкст:
Выкарыстоўвай існуючы стыль гэтага файла.

Межы:
Не змяняй іншыя файлы. Не дадавай бібліятэкі.

Праверка:
Запусці bun run lesson1_ai_ide/01_calculator.ts.
```

## 8. Інструкцыі, `AGENTS.md`, скілы і MCP

У гэтым уроку мы толькі знаёмімся з гэтымі паняццямі. Падрабязней яны з'явяцца далей у курсе.

### Інструкцыі

Інструкцыі — гэта пастаянныя правілы для AI:

```text
Адказвай па-беларуску.
Не дадавай залежнасці без патрэбы.
Перад шырокімі зменамі прапануй план.
Пасля змены кода падкажы каманду для праверкі.
```

### `AGENTS.md`

`AGENTS.md` — файл у рэпазіторыі з правіламі для агентаў. Ён дапамагае не паўтараць адны і тыя ж інструкцыі ў кожным prompt.

Мінімальны прыклад:

```markdown
# AGENTS.md

## Мова

Навучальныя тэксты пішы па-беларуску.

## Код

Выкарыстоўвай TypeScript і Bun.
Не дадавай залежнасці без тлумачэння.

## Праверка

Пасля змены TypeScript-файлаў падказвай каманду запуску.
```

### Скілы

Скіл — гэта паўторная інструкцыя або працэдура для агента. Напрыклад: "правярай кожны ўрок па адным чэклісце". У гэтым рэпазіторыі ёсць прыклад у `lessons12_skills`.

### MCP

MCP — спосаб даць AI доступ да інструментаў або дадзеных: пошуку, базы, API, файлавай сістэмы. У гэтым курсе MCP падрабязна разбіраецца ў [Уроку 8](file:///Users/serj/projects/lessons/RAG/lesson8_mcp).

Для першага ўрока дастаткова зразумець:

- prompt — разавая задача;
- інструкцыі і `AGENTS.md` — пастаянныя правілы;
- скіл — паўторная методыка;
- MCP — доступ да інструментаў і дадзеных.

## 12. Чэкліст пасля кожнай AI-змены

Пасля таго як AI нешта змяніў:

- паглядзіце diff;
- праверце, што змяніліся толькі патрэбныя файлы;
- запусціце адпаведны Bun-файл;
- прачытайце вывад;
- калі вынік не той, удакладніце prompt замест таго, каб прымаць выпадковую праўку.

Карысныя каманды:

```bash
git diff -- lesson1_ai_ide
bun run lesson1_ai_ide/index.ts
```
