## Што такое LangGraph?

**LangGraph** — гэта бібліятэка для стварэння **stateful, цыклічных AI-праграм** на аснове графаў. 

### Ключавыя канцэпцыі:

```
┌─────────────────────────────────────────────────────────────┐
│                      LangGraph                               │
├─────────────────────────────────────────────────────────────┤
│  📊 State (Стан)     - Даныя, якія перадаюцца паміж вузламі │
│  🔲 Nodes (Вузлы)    - Функцыі, якія апрацоўваюць стан      │
│  ➡️  Edges (Пераходы) - Сувязі паміж вузламі                 │
│  🔄 Cycles (Цыклы)   - Магчымасць вяртацца да папярэдніх    │
│  💾 Persistence      - Захаванне стану паміж сесіямі        │
└─────────────────────────────────────────────────────────────┘
```

### Чаму LangGraph, а не простыя ланцужкі?

| Простыя ланцужкі | LangGraph |
|-----------------|-----------|
| Лінейны паток A → B → C | Цыклічны паток з галінаваннем |
| Без стану | Поўнае кіраванне станам |
| Адзін выклік | Шмат ітэрацый да вынаходжання рашэння |
| Няма памяці | Persistence паміж сесіямі |

## Annotation: Кіраванне станам

### Што такое Annotation?

`Annotation` — гэта спосаб **вызначыць структуру стану** графа з указаннем:
- Тыпу даных для кожнага поля
- Як аб'ядноўваць (reduce) абнаўленні
- Значэнні па змаўчанні

### Сінтаксіс:

```typescript
import { Annotation } from '@langchain/langgraph';

const MyState = Annotation.Root({
    // Поле з reducer-ам і значэннем па змаўчанні
    fieldName: Annotation<ТыпДаных>({
        reducer: (currentValue, newValue) => /* як аб'яднаць */,
        default: () => /* пачатковае значэнне */,
    }),
});
```

### Прыклад з нашага кода:

```typescript
const ResearchState = Annotation.Root({
    // 📨 MESSAGES: Масіў паведамленняў (дадаюцца новыя)
    messages: Annotation<BaseMessage[]>({
        reducer: (curr, update) => [...curr, ...update],
        //        ▲               ▲
        //        │               └── Новыя паведамленні
        //        └── Існуючыя паведамленні
        // Вынік: [існуючыя..., новыя...]
        default: () => [],
    }),
    
    // 📝 TOPIC: Тэма (заменяецца поўнасцю)
    topic: Annotation<string>({
        reducer: (_, update) => update,
        //        ▲    ▲
        //        │    └── Новае значэнне (выкарыстоўваецца)
        //        └── Старое значэнне (ігнаруецца)
        default: () => '',
    }),
    
    // ... іншыя палі
});
```

### Віды Reducer-аў:

```typescript
// 1️⃣ ЗАМЕНА: Новае значэнне замяняе старое
reducer: (_, update) => update
// Прыклад: topic = "новая тэма" → topic = "новая тэма"

// 2️⃣ НАКАПЛЕННЕ: Новыя элементы дадаюцца да існуючых
reducer: (curr, update) => [...curr, ...update]
// Прыклад: messages = [msg1] + [msg2] → [msg1, msg2]

// 3️⃣ ІНКРЭМЕНТ: Павялічэнне лічыльніка
reducer: (curr, update) => curr + update
// Прыклад: count = 1 + 1 → 2

// 4️⃣ АБ'ЯДНАННЕ АБ'ЕКТАЎ: Merge аб'ектаў
reducer: (curr, update) => ({ ...curr, ...update })
// Прыклад: {a: 1} + {b: 2} → {a: 1, b: 2}
```

### Чаму гэта важна?

```
┌────────────────────────────────────────────────────────┐
│                    КОЖНЫ ВУЗЕЛ                         │
├────────────────────────────────────────────────────────┤
│                                                        │
│   1. Атрымлівае ПОЎНЫ стан                            │
│      state = { messages: [...], topic: "...", ... }   │
│                                                        │
│   2. Вяртае ЧАСТКОВАЕ абнаўленне                      │
│      return { messages: [newMsg], draft: "..." }      │
│                                                        │
│   3. LangGraph АЎТАМАТЫЧНА аб'ядноўвае                │
│      праз reducer-ы                                    │
│                                                        │
└────────────────────────────────────────────────────────┘
```

## StateGraph: Стварэнне графа

### Што такое StateGraph?

`StateGraph` — гэта **канструктар графа**, які дазваляе:
- Дадаваць вузлы (nodes)
- Вызначаць пераходы (edges)
- Кампіляваць у выканальную праграму

### Сінтаксіс стварэння:

```typescript
import { StateGraph } from '@langchain/langgraph';

const workflow = new StateGraph(ResearchState)
    // Дадаем вузлы
    .addNode('name1', function1)
    .addNode('name2', function2)
    
    // Дадаем пераходы
    .addEdge('__start__', 'name1')  // START → name1
    .addEdge('name1', 'name2')       // name1 → name2
    .addEdge('name2', '__end__');    // name2 → END
```

### Спецыяльныя вузлы:

```
┌─────────────────────────────────────────────────────┐
│  '__start__'  │  Уваходная кропка графа             │
├───────────────┼─────────────────────────────────────┤
│  '__end__'    │  Канчатковая кропка графа           │
└─────────────────────────────────────────────────────┘
```

### Наш прыклад:

```typescript
const workflow = new StateGraph(ResearchState)
    // Вузлы-агенты
    .addNode('researcher', researcherNode)   // 🔬
    .addNode('writer', writerNode)           // ✍️
    .addNode('reviewer', reviewerNode)       // 📖
    .addNode('finalizer', finalizerNode)     // 🏁
    
    // Лінейныя пераходы
    .addEdge('__start__', 'researcher')
    .addEdge('researcher', 'writer')
    .addEdge('writer', 'reviewer')
    
    // Умоўны пераход (цыкл або завяршэнне)
    .addConditionalEdges('reviewer', shouldContinue, {
        writer: 'writer',       // Вяртаемся да пісьменніка
        finalizer: 'finalizer', // Ідзём да фіналізатара
    })
    
    // Канчатковы пераход
    .addEdge('finalizer', '__end__');
```

## Вузлы (Nodes): Агенты

### Структура вузла:

```typescript
async function nodeName(
    state: ResearchStateType  // Уваходны стан (поўны)
): Promise<Partial<ResearchStateType>> {  // Частковае абнаўленне
    
    // 1. Чытаем патрэбныя даныя са стану
    const data = state.someField;
    
    // 2. Выконваем логіку (напрыклад, выклік LLM)
    const result = await model.invoke([...]);
    
    // 3. Вяртаем абнаўленні для стану
    return {
        someField: newValue,
        messages: [new AIMessage({ content: "..." })],
    };
}
```

## Пераходы (Edges): Сувязі

### Тыпы пераходаў:

```typescript
// 1️⃣ ПРОСТЫЯ (addEdge): Заўсёды ідзём у адзін вузел
workflow.addEdge('nodeA', 'nodeB');
//                 ▲         ▲
//                 │         └── Куды ідзём
//                 └── Адкуль ідзём

// 2️⃣ УМОЎНЫЯ (addConditionalEdges): Выбар на аснове стану
workflow.addConditionalEdges(
    'reviewer',           // З якога вузла
    shouldContinue,       // Функцыя, якая вяртае ключ
    {
        writer: 'writer',     // Калі вернецца 'writer' → ідзём у writer
        finalizer: 'finalizer' // Калі вернецца 'finalizer' → ідзём у finalizer
    }
);
```

### Візуалізацыя пераходаў:

```
ПРОСТЫЯ ПЕРАХОДЫ:
                    
    researcher ─────────► writer ─────────► reviewer
         │                                      │
         │                                      │
    (заўсёды)                              (заўсёды)


УМОЎНЫЯ ПЕРАХОДЫ:

                    ┌──────────────────────┐
                    │                      │
                    ▼                      │
              ┌──────────┐                 │
              │ reviewer │                 │
              └────┬─────┘                 │
                   │                       │
                   ▼                       │
           ┌──────────────┐                │
           │shouldContinue│                │
           └──────┬───────┘                │
                  │                        │
        ┌─────────┴─────────┐              │
        │                   │              │
        ▼                   ▼              │
   'finalizer'          'writer' ──────────┘
        │
        ▼
   finalizer
```

## Умоўныя пераходы

### Функцыя прыняцця рашэння:

```typescript
function shouldContinue(state: ResearchStateType): 'writer' | 'finalizer' {
    const review = state.review.toLowerCase();
    const maxIterations = 3;

    // Умова 1: Рэцэнзент сказаў "ЗАЦВЕРДЖАНА"
    if (review.includes('зацверджана') || review.includes('approved')) {
        return 'finalizer';  // ✅ Завяршаем
    }
    
    // Умова 2: Дасягнулі максімуму ітэрацый
    if (state.iterationCount >= maxIterations) {
        return 'finalizer';  // ⚠️ Прымусовае завяршэнне
    }
    
    // Інакш: Патрэбна дапрацоўка
    return 'writer';  // 🔄 Вяртаемся да пісьменніка
}
```

### Логіка ў выглядзе блок-схемы:

```
                    ┌─────────────────────────┐
                    │     shouldContinue      │
                    └───────────┬─────────────┘
                                │
                                ▼
                    ┌─────────────────────────┐
                    │ review.includes         │
                    │ ('зацверджана')?        │
                    └───────────┬─────────────┘
                                │
                    ┌───────────┴───────────┐
                    │                       │
                   ТАК                     НЕ
                    │                       │
                    ▼                       ▼
           ┌────────────────┐    ┌─────────────────────┐
           │return          │    │ iterationCount >= 3?│
           │'finalizer' ✅  │    └─────────┬───────────┘
           └────────────────┘              │
                                ┌──────────┴──────────┐
                                │                     │
                               ТАК                   НЕ
                                │                     │
                                ▼                     ▼
                       ┌────────────────┐   ┌────────────────┐
                       │return          │   │return          │
                       │'finalizer' ⚠️  │   │'writer' 🔄     │
                       └────────────────┘   └────────────────┘
```

## MemorySaver: Persistence

### Што такое MemorySaver?

`MemorySaver` — гэта **checkpointer**, які захоўвае стан графа пасля кожнага кроку.

```typescript
import { MemorySaver } from '@langchain/langgraph';

const checkpointer = new MemorySaver();

const app = workflow.compile({
    checkpointer,  // Дадаем checkpointer
});
```

### Для чаго гэта патрэбна:

```
┌─────────────────────────────────────────────────────────────┐
│                    БЕЗ CHECKPOINTER                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Запуск 1: START → researcher → writer → reviewer → END   │
│                                                             │
│   Запуск 2: START → researcher → ...  (з нуля!)            │
│                                                             │
│   ❌ Стан губляецца паміж запускамі                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                    З CHECKPOINTER                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Запуск 1: START → researcher → writer → [ЗАХАВАНА]       │
│                                            │                │
│                                    💾 thread_id: "abc"      │
│                                                             │
│   Запуск 2: [АДНАЎЛЕННЕ] → reviewer → END                  │
│                     │                                       │
│             💾 thread_id: "abc"                             │
│                                                             │
│   ✅ Можам працягнуць з месца спынення                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Thread ID:

```typescript
const config = {
    configurable: {
        thread_id: 'article-1',  // Унікальны ID для гэтай "размовы"
    },
};

// Першы запуск
await app.invoke({ topic: "LangChain" }, config);

// Пазнейшы запуск з тым жа thread_id
// Можна працягнуць або праверыць стан
const state = await app.getState(config);
```

### Тыпы Checkpointer-аў:

| Checkpointer | Апісанне | Выкарыстанне |
|--------------|----------|--------------|
| `MemorySaver` | У памяці (губляецца пасля перазапуску) | Распрацоўка, тэсты |
| `SqliteSaver` | SQLite база даных | Лакальныя праграмы |
| `PostgresSaver` | PostgreSQL | Прадакшн |
| `RedisSaver` | Redis | Хуткі доступ, кэшаванне |

## Выснова

LangGraph дазваляе ствараць **складаныя, цыклічныя AI-сістэмы** з:

1. **Выразным станам** — праз Annotation
2. **Модульнай архітэктурай** — праз вузлы-функцыі
3. **Гнуткай логікай** — праз умоўныя пераходы
4. **Надзейнасцю** — праз persistence

Гэта ідэальна для:
- Мульты-агентных сістэм
- Ітэратыўных працэсаў (напісанне → рэдагаванне → зацвярджэнне)
- Human-in-the-loop сцэнарыяў
- Складаных працоўных працэсаў з галінаваннем
