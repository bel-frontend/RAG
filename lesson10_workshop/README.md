# Lesson 10: MD-Рэцэнзент

Інтэлектуальны агент для праверкі і паляпшэння Markdown дакументаў з выкарыстаннем LangGraph.

---

## Практычная мэта воркшопа

Галоўная мэта гэтага воркшопа — сабраць невялікі, але карысны AI-інструмент для рэальнага працоўнага сцэнарыя: узяць Markdown-артыкул на беларускай мове, праверыць яго праз LLM, захаваць структуру дакумента і атрымаць выпраўленую версію побач з арыгіналам.

Пасля воркшопа ўдзельнік павінен разумець:

- як апісаць стан агента ў LangGraph;
- як разбіць Markdown на бяспечныя чанкі без паломкі код-блокаў;
- як зрабіць розныя рэжымы рэцэнзавання праз промпты;
- як запусціць паслядоўную і паралельную апрацоўку чанкаў;
- як ператварыць эксперымент з LLM у CLI-утыліту, якой можна карыстацца ў праекце.

## Што гэта такое?

**MD-Рэцэнзент** — гэта AI-агент, які аўтаматычна правярае тэхнічную дакументацыю на беларускай мове. Ён выкарыстоўвае LangGraph, каб выразна падзяліць працэс на этапы: аналіз дакумента, рэцэнзаванне чанкаў і фіналізацыю выніку.

### Ключавыя магчымасці

| Магчымасць | Апісанне |
|------------|----------|
| Рэжымы праверкі | Граматыка, стыль або поўная праверка |
| Паралельная апрацоўка | Апрацоўка некалькіх чанкаў адначасова для вялікіх файлаў |
| Разумнае разбіццё | Код-блокі захоўваюцца без зменаў |
| Ітэрацыі з лімітам | Калі тэкст змяніўся, агент робіць кантрольны праход і спыняецца па `MAX_ITERATIONS` |
| CLI-вынік | Выпраўлены файл захоўваецца як асобны Markdown-файл |

## Сцэнар занятку

1. Разабраць ўваходны артыкул `articles/mcp.md`.
2. Паглядзець, як `reviewer.ts` выдзяляе стан і вузлы LangGraph.
3. Запусціць рэцэнзаванне ў рэжымах `grammar`, `style` і `full`.
4. Параўнаць вынікі ў `articles/mcp_grammar.md` і `articles/mcp_reviewed.md`.
5. Разабраць, навошта патрэбны ліміт ітэрацый: агент можа паўторна праверыць свой вынік, але не павінен сыходзіць у бясконцы цыкл.
6. Абмеркаваць абмежаванні: LLM можа змяніць сэнс, таму вынік трэба рэв’юіць чалавекам.

## 🚀 Хуткі старт

### 1. Усталёўка

```bash
cd lesson10_workshop
bun install
```

### 2. Наладка

Стварыце файл `.env` у тэчцы `lesson10_workshop/`:

```env
OPENAI_API_KEY=sk-your-api-key-here
```

```bash
# Праверка файла (поўная праверка)
bun run start articles/mcp.md

# Толькі граматыка
bun run start articles/mcp.md --mode=grammar

# Паралельная апрацоўка вялікага файла
bun run start big-doc.md --mode=grammar --parallel
```

## 📖 Рэжымы праверкі

### `--mode=grammar` — Граматыка

Правярае толькі:
- Арфаграфічныя памылкі
- Памылкі друку
- Канчаткі слоў
- Склады і адмены

**Калі выкарыстоўваць:** Для хуткай праверкі перад публікацыяй.

### `--mode=style` — Стыль

Правярае толькі:
- Зразумеласць тлумачэнняў
- Паслядоўнасць тэрміналогіі
- Структуру сказаў
- Тон і рэгістр мовы

**Калі выкарыстоўваць:** Для паляпшэння чытальнасці дакументацыі.

### `--mode=full` — Поўная праверка (па змаўчанні)

Правярае ўсё:
- Граматыку і правапіс
- Пунктуацыю
- Стыль і яснасць
- Markdown фарматаванне

**Калі выкарыстоўваць:** Для глыбокай праверкі важных дакументаў.

---

## ⚡ Паралельная апрацоўка

Для вялікіх дакументаў (>5000 сімвалаў) рэкамендуецца выкарыстоўваць флаг `--parallel` або `-p`:

```bash
bun run start large-document.md --mode=grammar -p
```

### Як гэта працуе

1. **Аналіз** — дакумент разбіваецца на чанкі (~3000 сімвалаў)
2. **Класіфікацыя** — код-блокі пазначаюцца і не правяраюцца
3. **Паралельная праверка** — 2 чанкі адначасова
4. **Зборка** — вынікі аб'ядноўваюцца ў правільным парадку

### Параўнанне хуткасці

| Файл | Звычайны рэжым | Паралельны рэжым |
|------|----------------|------------------|
| 10 KB | ~60 сек | ~30 сек |
| 40 KB | ~250 сек | ~70 сек |
| 100 KB | ~600 сек | ~150 сек |

## 🏗️ Архітэктура

### Граф стану (StateGraph)

```
┌─────────────┐
│   START     │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Analyzer   │ ← Разбівае дакумент на чанкі
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Reviewer   │ ← Правярае кожны чанк
└──────┬──────┘
       │
       ▼
   ┌───────┐
   │ OK?   │ ← Тэкст не змяніўся або дасягнуты MAX_ITERATIONS
   └───┬───┘
       │
  ┌────┴────┐
  │         │
  ▼         ▼
┌────┐   ┌──────────┐
│ ✓  │   │ Reviewer │ ← Кантрольны праход па выпраўленым тэксце
└────┘   └──────────┘
  │
  ▼
┌─────────────┐
│  Finalizer  │ ← Захоўвае вынік
└─────────────┘
```

### Стан агента

```typescript
const MDReviewState = Annotation.Root({
    filePath: Annotation<string>,        // Шлях да файла
    originalContent: Annotation<string>, // Арыгінальны змест
    currentContent: Annotation<string>,  // Бягучы змест
    mode: Annotation<ReviewMode>,        // grammar | style | full
    useParallel: Annotation<boolean>,    // Паралельная апрацоўка
    chunks: Annotation<DocumentChunk[]>, // Чанкі дакумента
    score: Annotation<number>,           // Ацэнка 1-10
    approved: Annotation<boolean>,       // Зацверджана?
    iteration: Annotation<number>,       // Нумар ітэрацыі
});
```

## 🧠 Як гэта працуе (тэхнічныя дэталі)

### 1. Разбіццё на чанкі

Дакумент разбіваецца на часткі па правілах:
- Загалоўкі (`#`, `##`, `###`) — асобныя чанкі
- Код-блокі (` ``` `) — захоўваюцца цалкам
- Тэкст — разбіваецца на чанкі ~3000 сімвалаў

### 2. Праверка чанкаў

Кожны тэкставы чанк адпраўляецца ў `gpt-5-nano` з інструкцыяй:
- Выправіць памылкі згодна з рэжымам
- Вярнуць ТОЛЬКІ выпраўлены тэкст
- Захаваць Markdown фарматаванне

### 3. Фільтрацыя вываду

Адказ мадэлі ачышчаецца ад:
- Markdown-агароджаў (` ```markdown `)
- Каментароў мадэлі ("Тэкст без зменаў")
- Інструкцый, якія паўтараюцца

### 4. Зборка

Чанкі аб'ядноўваюцца ў правільным парадку з захаваннем структуры.

## ❓ FAQ

### Чаму код-блокі не правяраюцца?

Код-блокі змяшчаюць код на розных мовах праграмавання. Іх праверка патрабуе спецыялізаваных інструментаў (лінтэраў, кампілятараў), а не моўнай мадэлі.

### Колькі каштуе выкарыстанне?

Кошт залежыць ад актуальных тарыфаў OpenAI, памеру дакумента, колькасці ітэрацый і абранай мадэлі. Для воркшопа па змаўчанні выкарыстоўваецца `gpt-5-nano`, таму яго варта лічыць базавым танным варыянтам для частых запускаў на невялікіх Markdown-файлах.

### Ці можна выкарыстоўваць для іншых моў?

Так! Змяніце промпты ў `getModePrompt()` на патрэбную мову. Агент працуе з любой мовай, якую падтрымлівае GPT.
